# 校园实验室设备巡检与故障工单系统设计

## 目标

构建一个可在本机零依赖运行的毕业设计级全栈 Web 系统，演示 AgentTeam 从需求、设计、开发、测试到论文与答辩的完整交付链路。

## 用户与场景

| 角色 | 主要任务 |
|---|---|
| 实验室管理员 | 维护设备台账、查看总体状态、关闭已解决工单 |
| 巡检员 | 记录设备巡检结果，发现异常 |
| 维修人员 | 接收并推进故障工单 |

核心业务为设备登记、巡检记录、故障上报、工单状态流转和运营统计。

## 系统架构

- 前端：原生 HTML、CSS、JavaScript，单页工作台。
- 后端：Node.js 内置 `http` 模块，无第三方依赖。
- 数据：JSON 文件持久化，首次运行自动生成初始数据。
- API：REST/JSON，统一错误结构。
- 测试：Node.js 内置 `node:test`，覆盖 API 与状态流转。

## 数据模型

- `equipment`：编号、名称、位置、类别、状态、负责人、最近巡检时间。
- `inspection`：设备、巡检人、结论、备注、时间。
- `ticket`：设备、标题、严重程度、状态、处理人、创建和更新时间。

工单状态机：

```text
open -> assigned -> repairing -> resolved -> closed
```

不允许跳级或回退。

## API 契约

| 方法 | 路径 | 用途 |
|---|---|---|
| GET | `/api/health` | 健康检查 |
| GET | `/api/equipment` | 设备列表 |
| POST | `/api/equipment` | 新增设备 |
| GET | `/api/inspections` | 巡检记录 |
| POST | `/api/inspections` | 新增巡检 |
| GET | `/api/tickets` | 工单列表 |
| POST | `/api/tickets` | 新建工单 |
| PATCH | `/api/tickets/:id` | 推进工单 |
| GET | `/api/stats` | 汇总指标 |

## 视觉方向

设计语言来自实验室仪器面板和校准记录，而不是通用 SaaS 卡片。

- 底色：冷灰白 `#ECE9DF`
- 主面板：深石墨 `#1C2529`
- 结构色：仪器青 `#2F6D69`
- 警示色：校准黄 `#D7A33D`
- 故障色：安全红 `#B74336`
- 正文：墨黑 `#172124`

字体采用 `Segoe UI Variable` 作为界面文字，`Cascadia Mono` 用于设备编号和状态数据。主布局为左侧“实验台导轨”、中部“设备槽位矩阵”、右侧“故障纸带”，避免等宽圆角卡片堆叠。页面加载只保留一次仪器刻度展开动画，并尊重 `prefers-reduced-motion`。

## 验收标准

1. `npm start` 可启动系统。
2. 浏览器可新增设备、巡检、工单并推进工单。
3. 所有 API 有参数校验和明确状态码。
4. 自动化测试全部通过。
5. 具备需求、设计、六章论文、答辩大纲、演示脚本和预测 Q&A。
6. 全程只使用本地免费资源。
