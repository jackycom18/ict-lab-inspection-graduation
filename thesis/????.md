# 校园实验室设备巡检与故障工单系统的设计与实现

## 摘要

高校实验室设备类型多、巡检周期不统一，设备异常往往分散在纸质记录和即时通信消息中，难以形成可追踪的维修闭环。本文设计并实现一个面向实验室管理员、巡检员和维修人员的全栈 Web 系统。系统以设备台账、巡检记录、故障工单和运营统计为核心，通过严格的状态机约束维修流程，并使用浏览器工作台统一呈现设备状态与责任信息。

系统采用 Node.js 内置 HTTP 服务、原生 HTML/CSS/JavaScript 和 JSON 文件存储，不依赖第三方运行时包。后端实现 REST API、输入校验和状态转换控制；前端采用实验仪器面板式布局，提供设备登记、巡检提交、工单上报和状态推进功能。自动化测试覆盖健康检查、设备创建、巡检创建、工单状态机和统计接口，5 项测试全部通过。

**关键词：** 实验室设备；巡检；故障工单；Node.js；状态机；全栈 Web

## 第一章 绪论

### 1.1 研究背景

实验室设备管理通常涉及采购登记、定期巡检、故障上报、维修跟进和责任追溯。传统纸质记录便于现场填写，但难以统计和检索；普通即时通信工具提高了沟通速度，却容易造成工单状态不一致。将设备、巡检和维修记录统一到一个轻量系统，可以降低漏检和重复沟通。

### 1.2 研究目标

本课题的目标是构建一个可独立运行的毕业设计级系统，完成以下闭环：

1. 设备台账记录设备的身份、位置和责任人。
2. 巡检记录反映设备在特定时间的可用性。
3. 故障工单承载异常处理和状态责任。
4. 统计面板呈现设备运行状态与工单积压情况。

### 1.3 研究内容

主要工作包括需求分析、REST API 设计、工单状态机实现、响应式工作台开发、自动化测试、论文撰写和答辩材料整理。项目同时作为 AgentTeam 多角色协作示例，将需求、设计、开发、测试、论文和答辩产物纳入同一仓库。

## 第二章 需求分析

### 2.1 用户角色

实验室管理员负责设备台账和总体状态；巡检员按设备记录正常或异常；维修人员接收工单并推进维修流程。不同角色的操作围绕同一组设备数据展开。

### 2.2 功能需求

系统提供设备查询与登记、巡检创建、故障工单创建、工单指派与推进、运营统计和错误提示。功能需求编号为 FR-01 至 FR-08，详细内容见《需求规格说明书》。

### 2.3 非功能需求

系统需在 Node.js 18 以上环境直接运行，默认仅监听本机地址，不使用第三方运行依赖；接口需校验参数和请求体大小；前端需具备键盘焦点和响应式布局。

### 2.4 业务边界

本系统不连接真实仪器控制器，不包含统一身份认证和短信通知。数据采用单进程 JSON 文件持久化，适用于课程演示和小规模单机使用，不适合高并发生产环境。

## 第三章 系统设计

### 3.1 总体架构

浏览器通过 JSON/HTTP 调用 Node.js HTTP 服务。服务层的 `app.mjs` 负责路由、校验、状态转换和静态文件，`store.mjs` 负责业务编号、持久化和统计。数据写入 `data/lab-db.json`。

### 3.2 数据模型

设备实体包含编号、名称、位置、类别、状态、负责人和最近巡检时间。巡检实体引用设备并保存巡检人、结论和备注。工单实体引用设备并保存严重程度、状态、处理人和时间信息。

### 3.3 工单状态机

工单按 `open → assigned → repairing → resolved → closed` 单向前进。为待领取工单指定处理人时自动进入 `assigned`。非法跳级或回退返回 HTTP 409，避免系统出现未维修即关闭等不一致状态。

### 3.4 前端设计

界面采用实验室仪器工作台语言：深石墨控制导轨、冷灰白网格背景、仪器青状态区、校准黄和故障红。中部设备阵列使用槽位式横向标识表达设备状态，右侧操作台集中放置三个业务表单。

## 第四章 系统实现

### 4.1 后端实现

服务使用 `node:http` 创建。路由覆盖健康检查、设备、巡检、工单、工单更新和统计接口。请求体通过异步流读取，超过 1 MB 返回 413。所有错误统一以 `{error:{code,message}}` 返回。

设备、巡检和工单在插入时由仓库自动生成 `EQ-`、`IN-`、`WO-` 编号。每次写入后同步持久化 JSON 文件，保证重新启动后数据仍可读取。

### 4.2 前端实现

浏览器应用并行请求设备、巡检、工单和统计数据。渲染函数使用 `document.createElement` 与 `textContent` 写入业务字段，避免将用户输入解释为 HTML。设备下拉框在数据刷新后同步更新。

### 4.3 工单交互

工单按钮根据当前状态显示“领取工单、开始维修、标记解决、关闭工单”。点击后发送 PATCH 请求，后端验证目标状态是否等于状态机的下一个状态，成功后刷新整页数据。

### 4.4 可访问性与响应式

表单控件均有标签；链接、按钮和输入控件使用统一的可见焦点样式。页面在 1180 像素和 760 像素设置响应式断点，并在 `prefers-reduced-motion` 下关闭动画。

## 第六章 总结与展望

本文完成了一个从需求到答辩材料的实验室设备巡检系统。系统以较小的技术栈实现了设备、巡检、工单和统计的完整数据流，并通过状态机确保维修流程可追踪。项目同时验证了 AgentTeam 按角色拆分产物、再通过契约和测试整合的方法。

后续工作可包括：接入校园统一身份认证；增加设备二维码扫码巡检；使用关系数据库替换 JSON 文件；增加维修备件、消息通知和设备折旧统计；通过历史巡检数据建立故障预测模型。
