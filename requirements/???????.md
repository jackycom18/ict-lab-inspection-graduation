# 校园实验室设备巡检与故障工单系统需求规格说明书

## 1. 项目背景

高校实验室设备数量多、责任人分散，纸质巡检记录与即时通信工具中的故障信息难以追踪。系统将设备台账、巡检结论和维修工单放在同一工作台，形成可查询、可统计、可交接的闭环。

## 2. 用户角色

| 角色 | 目标 |
|---|---|
| 实验室管理员 | 维护设备信息，掌握运行状态和工单完成情况 |
| 巡检员 | 按设备提交巡检结果和异常说明 |
| 维修人员 | 领取、维修、解决和关闭故障工单 |

## 3. 功能需求

| 编号 | 需求 |
|---|---|
| FR-01 | 系统应展示设备编号、名称、位置、类别、状态、负责人和最近巡检时间。 |
| FR-02 | 用户应能登记新设备并设置运行、维护或停用状态。 |
| FR-03 | 巡检员应能对指定设备记录正常或异常，并填写备注。 |
| FR-04 | 用户应能针对设备创建低、中、高三种严重程度的故障工单。 |
| FR-05 | 工单必须按 `open → assigned → repairing → resolved → closed` 顺序推进。 |
| FR-06 | 首页应显示设备总数、运行设备数、未结工单、高优先故障和完成率。 |
| FR-07 | API 应以 JSON 返回统一错误码和中文错误消息。 |
| FR-08 | 前端应提供设备、巡检、工单和统计的一屏式操作工作台。 |

## 4. 非功能需求

| 编号 | 需求 |
|---|---|
| NFR-01 | 运行时不依赖第三方包，Node.js 18 以上即可启动。 |
| NFR-02 | 数据写入本地 JSON 文件，重启后仍可读取。 |
| NFR-03 | 默认只监听 `127.0.0.1`，不暴露到公网。 |
| NFR-04 | 表单控件有标签和可见键盘焦点，动画尊重减少动态效果设置。 |
| NFR-05 | API 请求体上限 1 MB，对必填字段、枚举和状态流转进行校验。 |
| NFR-06 | 桌面、平板和手机宽度下均保持可操作。 |

## 5. 业务规则

1. 工单从创建开始为 `open`。
2. 为未领取工单指定处理人时，状态自动变为 `assigned`。
3. 已关闭工单不能继续推进。
4. 巡检结论只能为 `pass` 或 `issue`。
5. 高优先故障指严重程度为 `high` 且尚未关闭的工单。

## 6. 验收条件

- 设备、巡检和工单可新增并持久化。
- 非法输入返回 HTTP 400。
- 不存在的设备或工单返回 HTTP 404。
- 跳过工单状态返回 HTTP 409。
- 自动化测试全部通过。
- 浏览器页面可完成主要操作和指标刷新。
