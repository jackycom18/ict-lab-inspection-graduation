# 系统设计文档

## 1. 设计目标

系统以单机演示环境为前提，使用浏览器、Node.js 和本地 JSON 文件完成全栈闭环。重点展示清晰的数据模型、API 契约、状态机和人机协作工作台，而不是依赖重型框架。

## 2. 分层结构

```text
Browser
  ├─ index.html       页面语义结构
  ├─ styles.css       仪器面板视觉系统
  └─ app.js           API 调用与 DOM 渲染
        │ JSON/HTTP
Node.js HTTP Server
  ├─ app.mjs          路由、校验、状态机、静态文件
  └─ store.mjs        JSON 持久化与统计
        │
data/lab-db.json      本地数据文件
```

## 3. 模块职责

- `backend/app.mjs`：URL 路由、请求体读取、字段校验、错误映射、工单状态机。
- `backend/store.mjs`：初始数据、业务 ID、插入记录、持久化和统计。
- `backend/server.mjs`：读取环境配置并监听 `127.0.0.1:3000`。
- `frontend/app.js`：并行加载 API 数据、渲染工作台、提交表单和推进工单。
- `frontend/styles.css`：实验室仪器面板风格、状态颜色和响应式布局。

## 4. 工单状态机

```text
open ──领取──> assigned ──开工──> repairing
                                  │
                              标记解决
                                  ▼
                              resolved ──关闭──> closed
```

后端拒绝跳级、回退和关闭后继续推进，返回 `409 INVALID_TRANSITION`。

## 5. 错误模型

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "设备名称必填"
  }
}
```

- 400：参数或状态值不合法。
- 404：设备、工单或 API 不存在。
- 409：工单状态转换冲突。
- 413：请求体超过 1 MB。

## 6. 持久化

首次启动自动写入种子数据。每次新增或更新后同步写回 JSON 文件。系统不处理并发多进程写入，定位为单机课程设计演示。

## 7. 前端视觉与交互

- 左侧深色实验台导轨承担导航和时间显示。
- 中部设备阵列以仪器槽位表达状态，维护和停用设备通过顶边警示色区分。
- 右侧操作台统一放置设备、巡检和故障表单。
- 工单推进按钮按状态机显示“领取、开工、解决、关闭”。
- 所有用户文本使用 `textContent` 写入，避免 HTML 注入。
